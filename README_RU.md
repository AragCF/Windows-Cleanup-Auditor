# Ревизор дискового мусора для Windows

**Версия 0.2.4**

Утилита сначала исследует выбранный локальный диск или все фиксированные диски, показывает найденные объекты по категориям, размеру и степени риска и только затем позволяет удалить явно выбранные объекты.

## Степени риска

- **Безопасно** — временные данные и промежуточные результаты, которые обычно создаются заново.
- **Восстанавливаемое** — кэши и загружаемые зависимости, удаление которых может потребовать повторной загрузки или сборки.
- **Осторожно** — объекты, которые программа никогда не выбирает как безопасные автоматически: виртуальные среды, `node_modules`, локальные `.ipa`, скачанные установщики и архивы и т. п.

Исходный код, `.git`, Android SDK и Flutter SDK целиком, AVD, ключи, пользовательские документы и системные хранилища Windows не считаются мусором.

## Запуск

Для первого прогона:

```bat
scan_only.bat
```

Этот режим **ничего не удаляет** и сохраняет JSON/CSV в `reports\`.

Графический режим:

```bat
start_cleanup.bat
```

BAT-файлы версии 0.2.4 записаны в ASCII с окончаниями CRLF и **не вызывают `chcp`**. Они не меняют кодовую страницу, шрифт или привычный вид `cmd.exe`; русский интерфейс находится в Python-приложении.

## Что распознаётся

Windows TEMP и CrashDumps; Gradle/Android; Flutter/Dart; Python; Maven; npm/Yarn/pnpm; NuGet; Cargo; CMake; кэши Android Studio/JetBrains/VS Code; промежуточные каталоги проектов.

Отдельно учитываются:

- `Flutter SDK\bin\cache` — восстанавливаемый кэш; сам Flutter SDK целиком не удаляется.
- `Android\Sdk\.temp` — временные загрузки Android SDK Manager.
- верхнеуровневые ZIP/7z/RAR/EXE/MSI рядом с Android SDK — показываются по одному как **«Осторожно»**; это часто старые установщики и архивы, но решение остаётся за пользователем.
- локальные `.ipa` внутри профиля iMazing — показываются по одному как **«Осторожно»**. Их удаление с компьютера не удаляет уже установленное приложение с iPhone, но уничтожает локальную копию для будущей переустановки.

Каталоги `ndk`, `build-tools`, `platforms`, `platform-tools` и сам `flutter` внутри SDK — это рабочие компоненты, а не мусор. Удаление устаревших версий таких компонентов должно быть отдельной осознанной операцией.

## Публичный Git и журналы

`logs/` и `reports/` исключены через `.gitignore`: в них могут попасть имя пользователя, пути и названия проектов.

Для передачи результатов:

```bat
pack_reports_for_git.bat
```

Нужен установленный 7-Zip. Пароль запрашивает сам 7-Zip в своей консоли; используйте согласованный пароль. Упаковщик создаёт `encrypted_reports\WCA_reports_*.7z` с AES-256 и шифрованием имён файлов (`-mhe=on`). Пароль в репозитории не хранится. Исходные открытые отчёты автоматически не удаляются.

## Безопасность удаления

Перед удалением цель повторно проверяется. Запрещено удаление корней дисков, системных корней, ссылок/точек повторного разбора и объектов внутри систем контроля версий. Для категории **«Осторожно»** требуется дополнительное подтверждение словом `УДАЛИТЬ`.

## Проверки 0.2.0

В среде разработки подтверждены синтаксис Python, самопроверка правил, защитные проверки удаления, обнаружение Android/Gradle/Flutter/Python, локальных iMazing IPA и архивов рядом с Android SDK, исключение `.git`, а также ASCII+CRLF для BAT-файлов.

Запуск через настоящий `cmd.exe`, отображение графического окна и реальное удаление на рабочей Windows-машине должны быть подтверждены отдельной полевой проверкой.


## Исправление 0.2.1

- Сканирование всех дисков больше не является поведением по умолчанию.
- `scan_only.bat` без параметров сканирует только системный диск.
- `scan_only.bat C:` и аналогичные вызовы позволяют явно выбрать один диск.
- Полный обход всех фиксированных дисков доступен только через `scan_only.bat ALL` или параметр `--all-drives`.
- В графическом окне по умолчанию выбран только системный диск; остальные диски остаются снятыми.


## Исправление 0.2.2

В 0.2.1 BAT-файл добавлял обратную косую черту к корню диска перед передачей заключённого в кавычки аргумента. В Windows это приводило к фактическому аргументу вида `C:"`, поэтому сканирование завершалось мгновенно с нулём находок. В 0.2.2 BAT передаёт `C:` как `C:` без завершающей черты в кавычках, а Python нормализует букву диска самостоятельно. Добавлена также защита от уже искажённого аргумента вида `C:"`.


## Исправление 0.2.3

Реальный проход по диску C: выявил несколько слишком смелых эвристик 0.2.2. Версия 0.2.3 усиливает защиту:

- глубокий обход больше не заходит внутрь Windows, Program Files, Program Files (x86), LocalAppData\\Programs и обнаруженных деревьев Miniconda/Anaconda;
- обнаруженные Android SDK, Flutter SDK и отдельные установки Python не разбираются как обычные проекты;
- при этом известные безопасные кэши (например Flutter bin\\cache и Android SDK .temp) по-прежнему учитываются отдельными правилами;
- каталоги build/.gradle и другие артефакты внутри папок *.bak больше не считаются безопасными: они переводятся в категорию «Осторожно», чтобы не менять резервную копию без явного решения;
- физически одинаковые объекты, доступные через разные пути/ссылки, не должны дважды учитываться в итоговом объёме;
- мелкие глубокие кандидаты ниже порога больше не засоряют консоль строками «Подсчёт»;
- удаление потомков системных и установочных деревьев дополнительно блокируется непосредственно перед операцией удаления.

Отчёт 0.2.2 полезен как диагностический материал, но использовать его список «Безопасно» для автоматического удаления не следует: в нём были ложные кандидаты внутри установленных программ.


## Исправление 0.2.4

Добавлена полноценная защита от символических ссылок, Windows junction и других точек повторного разбора:

- глубокий обход не входит в такие каталоги и считает число пропущенных ссылок;
- проверяется не только сам кандидат, но и каждый родительский компонент его пути;
- удаление через путь, который хотя бы на одном уровне проходит через ссылку/junction, запрещено;
- известные пути Android SDK, Flutter SDK и других инструментов, если они заданы через ссылку, сначала переводятся в физический канонический путь;
- несколько имён одного физического каталога объединяются и не должны дважды попадать в итоговый объём.

Например, если `%LOCALAPPDATA%\Android\Sdk` является junction на другой каталог, программа не обходит дерево через этот псевдоним и работает только с реальным физическим расположением.
